# Change Log — 2026-09-08: AIOps Pipeline Fixes & Server Setup

Comprehensive record of all changes made on 2026-09-08, on branch
`fix/aiops-pipeline` (repo changes, commit `e44b0ec`) and directly on the

---

## Part 1 — Why these changes were needed

1. **The AIOps monitoring chain was dead on arrival.** The README promised a
   `configs/prometheus.yml` that did not exist, Prometheus scraped nothing,
   and the AI metric file written by `ai_monitor.py` was never read by any
   collector.
2. **The Big-AGI UI could not reach Ollama** because its config pointed at
   `localhost` from inside a container.
3. **`ERR_CONNECTION_REFUSED` on `http://localhost:11434/`**: Ollama was not
   installed on this server at all — no binary, no systemd unit, nothing
   listening on port 11434.
4. **Network constraint discovered during setup:** this host's route to
   GitHub (and `ollama.com`, which redirects there) and Docker Hub is
   throttled to < 50 KB/s, while other CDNs (Cloudflare) run at multi-MB/s
   speeds. See Part 4 for the workaround used.

## Part 3 — Host/system changes (fixing the connection-refused error)

These were made directly on this server (Ubuntu, `sudo` available) and are
not version-controlled:

### 3.1 Ollama v0.33.3 installed
- Official `install.sh` abandoned after it stalled at < 50 KB/s on the
  throttled GitHub route.
- Instead: downloaded the official release asset
  `ollama-linux-amd64.tar.zst` (1.43 GB, v0.33.3) via a GitHub mirror proxy
  (`gh-proxy.com`, ~4 MB/s), verified the tarball, extracted:
  ```bash
  sudo tar --zstd -xf /tmp/ollama-linux-amd64.tar.zst -C /usr/local
  ```
  → `/usr/local/bin/ollama` + `/usr/local/lib/ollama/` (CUDA/runner libs).
- Temp tarball deleted after install.

### 3.2 System user
```bash
sudo useradd -r -s /bin/false -m -d /usr/share/ollama ollama
```
Owns `/usr/share/ollama/.ollama` (the model store).

### 3.3 Systemd unit `/etc/systemd/system/ollama.service` (NEW)
```ini
[Unit]
Description=Ollama Service
After=network-online.target

[Service]
ExecStart=/usr/local/bin/ollama serve
User=ollama
Group=ollama
Restart=always
RestartSec=3
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_ORIGINS=*"

[Install]
WantedBy=default.target
```
Enabled and started: `sudo systemctl enable --now ollama`.

This implements the README's troubleshooting requirements
(`OLLAMA_HOST` on all interfaces, `OLLAMA_ORIGINS="*"`).

### 3.4 Model pulled
`ollama pull deepseek-coder:1.3b` — 776 MB, pulled from the Ollama registry
(the registry route was not throttled).

### 3.5 Verification (all passed)
- `curl http://localhost:11434/` → `Ollama is running`

## Part 4 — Network constraint & workaround (for future installs)

Symptom: `github.com`, `ollama.com`, and Docker Hub downloads proceed at
< 50 KB/s from this host, while Cloudflare-fronted endpoints run at ~3.5 MB/s.
This is a route/peering issue on the local network, not a general outage.

Workaround that worked:
1. Resolve the desired asset URL from the GitHub API.
2. Prefix it with a GitHub release mirror (e.g. `https://gh-proxy.com/`).
3. Pull the Ollama model itself normally — `registry.ollama.ai` is not
   affected.

If Docker Hub images (`prometheus`, `grafana`, the UI images) pull too
slowly, use a registry mirror (e.g. configure `registry-mirrors` in
`/etc/docker/daemon.json`) or pull during a window when the route recovers.
